# MaxTag 中文使用指南

MaxTag 的目标不是让群成员学习一个复杂平台，而是：**管理员配置一次，成员把 Bot 拉进群并 @ 它即可工作。**

## 1. 管理员只需配置一次

在 MaxTag 管理台完成以下项目：

1. **飞书 Bot**：保存 App ID / App Secret，消息使用长连接；互动卡片回调配置为 `https://<你的域名>/v1/lark/events`。
2. **真实执行器**：选择本机已登录的 Codex CLI / Claude CLI，或使用平台加密托管的 API Key。
3. **Workspace 与 Project**：Workspace 表示公司边界，Project 表示项目边界。
4. **按需能力**：在 Project 中启用 Skills、子智能体、知识源、工具、网络白名单和预算。
5. **外部身份**：需要写 GitHub、飞书文档或 Base 时，为 Project 绑定对应的 Agent Identity；凭据只保留在 MaxTag 主机中。

配置完成后，普通成员不需要登录 MaxTag 管理台。

## 2. Bot 首次入群

1. 把 MaxTag Bot 添加到飞书群。
2. 在群里发送 `@MaxTag 你好`。
3. 首次接入卡片中选择已有 Project，或直接创建 Project。
4. 选择历史处理方式：
   - **从现在开始**：不读取旧消息；
   - **导入最近 30 天**：后台拉取、分批整理并显示进度。
5. 初始化完成后，群成员直接在群里 @MaxTag 即可。

一个 Project 可以绑定多个群；一个群同一时间只归属一个 Project。管理员可以在管理台重新绑定。

## 3. 日常怎么用

### 直接交办

```text
@MaxTag 帮我梳理这个项目最近的风险和下一步
@MaxTag 查看代码，修复这个错误并跑测试
@MaxTag 根据群里的决定整理一份发布方案
```

默认响应模式是 **仅被 @ 时**，因此普通闲聊不会触发卡片或模型调用。

### 查看帮助、能力与当前 Project

```text
@MaxTag 帮助
@MaxTag 状态
@MaxTag 你能访问什么？
```

这些命令不调用模型。卡片会显示当前 Workspace、Project、群聊/话题、触发方式、记忆范围、Skills、子智能体、知识源、工具、网络策略、持续任务和预算。

管理员或 Project 管理员可以直接在卡片中切换：

- 仅被 @ 时（默认）
- 回答明确问题
- 持续响应

### 长任务协作

长任务会持续更新同一张进度卡，显示步骤、工具调用、子智能体、待确认事项和恢复状态。

- 继续补充要求：在同一话题回复即可；
- 不想继续：点击 **停止**；
- 想人工处理：点击 **接管**；
- 需要外部写入：在精确参数审批卡上批准或拒绝。

服务重启后，已落库的运行、追问和审批会继续恢复，不需要重新发任务。

### 交互式图表和报告

```text
@MaxTag 生成一个交互式发布健康报告，并以后持续更新
```

MaxTag 会返回稳定链接。同一 Workspace + Project + 报告键后续更新时链接不变、版本递增；另一个 Project 会得到不同链接。报告无法访问外网，但可以使用自包含的 HTML、CSS 和 JavaScript 做筛选、图表和交互。

### 定时任务

```text
@MaxTag 每天 09:00：总结项目进展
@MaxTag 每 30 分钟：检查发布状态
@MaxTag 定时任务
@MaxTag 定时任务帮助
```

创建、暂停、恢复和删除是受审计写操作；需要审批时会在群里出现卡片。

### Skills、子智能体和知识源

管理员先在管理台启用能力，群成员再用自然语言调用：

```text
@MaxTag 用发布复核 Skill 检查这次上线
@MaxTag 请发布检查员并行核对 CI 和变更风险
@MaxTag 根据已接入的发布手册回答这个问题
```

MaxTag 只向当前 Project 暴露已启用的项目能力，不会看到其他 Project 的资源。

## 4. 记忆如何工作

MaxTag 的上下文由两部分组成：

1. 当前群聊/话题的有限近期上下文；
2. MaxTag 自己数据库中的已批准、可检索记忆。

群聊累计约 200 条新消息后会后台整理一次。已经被摘要覆盖的原始上下文在宽限期后清理，不会把整段群聊永久塞进模型。

记忆按边界隔离：

- **公司记忆**：Workspace 内所有获授权 Project 可继承；
- **项目记忆**：只属于当前 Project；
- **群聊/话题记忆**：只属于对应群或话题。

可用命令：

```text
@MaxTag 查看记忆 项目
@MaxTag 查看记忆 工作区
```

涉及替换、合并或删除既有事实时，MaxTag 使用版本校验，避免旧卡片覆盖新记忆。

## 5. 外部操作与身份审计

对 GitHub issue/comment、飞书文档追加、Base 记录创建/更新等外部写操作：

1. MaxTag 先展示精确参数；
2. 有权限的人批准后才执行一次；
3. 执行前再次检查 Project 授权和 Agent Identity revision；
4. 完成卡片显示请求智能体、凭据身份、外部 actor 和 **查看外部结果**；
5. 同一结果链接进入后续任务、Activity、Organization Audit 和 CSV 导出。

参数值、原始响应和凭据不会进入组织审计。

## 6. 常见问题

### 群里聊天时 MaxTag 突然介入

发送 `@MaxTag 状态`，把响应方式切回 **仅被 @ 时**。

### `code: 200671`

通常表示飞书互动卡片回调失败。确认卡片回调地址是 `/v1/lark/events`，Verification Token / Encrypt Key 与 MaxTag 保存值一致，并重新发送一张新卡片测试。旧卡片可能绑定旧回执，不能作为最终验证。

### `Lark API request failed with HTTP 504`

表示飞书 API 网关超时，不代表 Codex 本身失败。MaxTag 会保留运行和回执并按可重试策略恢复；若持续出现，在 Activity 中查看具体失败步骤。

### `memory_proposal_stale_document_version`

审批卡创建后，对应记忆文档已经被其他操作更新。旧卡片被安全拒绝，避免覆盖新内容；重新发起记忆整理即可。

### “已失效”

旧审批、旧回调回执或已被新版本替代的操作不能再次执行。这是幂等与版本保护，不是记忆丢失。

## 7. 与 Claude Tag 目标体验的对照

| 目标体验 | MaxTag 当前方式 |
| --- | --- |
| Bot 拉进群即可用 | 管理员一次配置；成员入群卡片选择/创建 Project |
| 不打扰闲聊 | 默认仅 @；可切换明确问题/持续响应 |
| 长任务可观察、可追问 | 同一卡片进度、同话题追问、停止、接管、恢复 |
| 跨会话持续理解 | 有限近期上下文 + MaxTag 自有分层记忆 |
| 项目能力可配置 | Skills、子智能体、知识源、工具、网络、预算按 Project 路由 |
| 生成可持续更新的产物 | 托管文件、PR/link、稳定链接交互报告 |
| 代表团队操作外部系统 | Agent Identity + 精确参数审批 + 外部结果回链 |
| 管理员可证明发生了什么 | 运行时间线、回执、用量、Organization Audit、CSV |

MaxTag 仍坚持两个边界：**不把群聊无差别永久保存为模型上下文；不允许模型绕过 Project 授权和人工审批直接写外部系统。**
